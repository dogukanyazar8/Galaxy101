# Galaxy 101 1a Unity UI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for coordination and superpowers:test-driven-development for behavior. Independent data, effects and window work may run in parallel under dispatching-parallel-agents.

**Goal:** Reproduce the supplied 1a menu and every specified window, interaction, theme, animation and TR/EN string in native Unity UI Toolkit.

**Architecture:** A separate Galaxy101 UI assembly and Bootstrap menu document replace the old menu while preserving the existing Okey101 rules and table. JSON-backed mock services feed separate screen controllers; modal navigation is centralized. Planet rendering uses baked equirectangular maps and an HLSL port, with a lightweight starfield. HTML is reference only, never a webview.

**Tech Stack:** Existing Unity6000.6.6f1/URP17.6, UI Toolkit UXML/USS/C#, Unity Localization, Montserrat/Baloo2 fonts.

**Spec:** Design/galaxy101_unity_handoff/PROMPT_CLAUDE_CODE.md, README.md, spec/01..07, data, all54screenshots; reference HTML1a wins conflicting visual values.

## Global Constraints

- User explicitly requested implementation of this supplied written design; no new design direction or reapproval of supplied screens. Bot mode opens existing local table (async user confirmation); other modes emit selection/play events without inventing online gameplay.
- Mock economy/friends/rewards/accounts are explicitly authorized by the design. No real payments, account deletion, network messages or cloud deployment.
- Reference1280x720, match.5; 1920x1080/2560x1440 must remain sharp. ThemeSaturn,16seconds/rotation,TR default.
- Preserve existing gameplay and saved scene customizations. Split build from automatic asset generation before integrating authored menu. Never initialize Git or commit (no repository).
- No foreground desktop automation or 30minute performance run. Own offscreen player/framebuffer only; user can test the final package.

## Review Focus

1. Duplicate CSV keys and ambiguous words must not discard translations.
2. Settings cancel must not claim persistence; language/theme immediate behavior must be explicitly recorded.
3. Nested modal keyboard/pointer input must not reach underlying controls.
4. Reward claims and friend requests must be idempotent.
5. Disabled animation must freeze time without a jump on resume and without leaked GPU resources.

## Shared implementation interfaces

Namespace `Galaxy101`. Services own `MenuModel`, `MenuServices`, `LocalizationBridge` (see services contract below). UI root owns `MenuView`, common primitives, styles, `ModalStack` and `MainMenuController`. Panel workers create `SettingsController`, `ShopController`, `FriendsController`, `LeaderboardController`, `DailyRewardController`, `RulesController`, `ProfileController`, and dialog controllers. Each consumes `MenuView` and returns a native `VisualElement` body.

### Services contract

`MenuModel` exposes `JObject Content`, `JObject Themes`, `JObject Settings`, `JObject Profile`, `int SelectedMode`, `string Planet`, `long Chips`, `long Gems`, `HashSet<string> Invited`, `HashSet<string> RequestsHandled`, `HashSet<string> SentRequests`, `HashSet<int> QuestsClaimed`, `bool DayClaimed`. Profile keys: name, color, status, frame(int). Settings keys exactly content.settingsDefaults plus resolution(int720/1080/1440). Methods `Persist()`, `NotifyChanged()`, event `Action Changed`. Constructor accepts data JSON strings + persistence path, or runtime factory LoadsResources. `MenuServices` constructor(MenuModel); named interface properties Profile/Economy/Friends/Leaderboard/Rewards/Settings/Share. Data operations should use JObject/JArray where original shape is heterogeneous. `LocalizationBridge.Text(string tr,string en=null)`, `SetLanguage(string)`, `Language`, event Changed; resolves all CSV rows with unique generated localization table keys.

### UI contract

`MenuView` exposes `MenuModel Model`, `MenuServices Services`, `LocalizationBridge Loc`, `VisualElement Root`, `string L(string tr,string en=null)`, `string N(long)`, `string P(int)`, `Color C(string)` (theme variable or HTML hex/rgba), `void Refresh()`, `void OpenPanel(string,int? tab=null)`, `void OpenDialog(string)`, `void CloseTop()`, `void Toast(string)`, `void Copy(string)`, `int Tab(string)`, `void SetTab(string,int)`. UI construction primitives `VisualElement Box(string classes="")`, `Label Text(string,int size=15,bool heading=false,string color=null)`, `Button Button(string,Action,string classes="primary")`, `VisualElement Row(params VisualElement[])`, `VisualElement Column(params VisualElement[])`, `VisualElement Avatar(int size,JObject profile=null,bool level=false)`, `VisualElement Icon(string,int size=24,string color=null)`, `VisualElement Tile(string code,int width=46,int height=62)`, `VisualElement Progress(float,string color=null)`, `ScrollView Scroll()`, `void Decorate(VisualElement,string background,int radius=0,int shadow=0,string shadowColor=null)`.

Each panel implements `public VisualElement Build(MenuView view)` and `public string[] Tabs(MenuView view)` if tabbed. Settings includes its own900x560layout and footer. Dialog controllers implement Build(MenuView view); modal shell owns centering, backdrop, animation,Esc,focus restoration. Root stores session tabs and draft profile/settings; workers may add their own private controller state, not rebuild root per keystroke.

### Effects contract

`GalaxyBackground : MonoBehaviour` has `void Initialize(VisualElement target)`, `void Configure(string planet,bool motion,string quality)`, `void SetFocused(bool)`, owns render targets/materials/camera/mesh resources and disposes on destroy. UI target is full1280x720 scaled by PanelSettings; output uses its screen mapping. Planet/star math must follow reference JS and spec; all supplied texture seeds preserved.
